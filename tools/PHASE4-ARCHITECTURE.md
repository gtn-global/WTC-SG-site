## 4.1 中英文页面级样式/脚本去重

### 现状
- `index.html`（中文，约 2010 行 / ~77KB）与 `index-en.html`（英文，约 4900 行 / ~210KB）
  为两份独立手写 HTML，16 屏结构基本一致，差异**仅在中英文案**。
- 样式：中文已抽离 `page.css`；英文仍为 inline `<style>`（Phase 2 时用户要求英文版不动）。
- 公共逻辑：`common.css` / `common.js` 已共享。

### 方案 A（推荐，低风险）：仅统一英文版内联样式
- 将 `index-en.html` 的内联 `<style>` 也抽为 `page-en.css`，使两版引用方式一致，
  后续改样式只动一个地方。
- 不触碰 HTML 骨架，回归风险极低。约 0.5 天。

### 方案 B（彻底去重，高风险）：数据层 + 模板
- 抽取 16 屏文案为 `content.cn.json` / `content.en.json`，HTML 改为共享模板 +
  构建脚本注入。需引入 Node 构建步骤（目前纯静态、无构建）。
- 收益：两版永不失同步；代价：破坏现有"双击即开"的纯静态特性，
  需 CI/构建产物，且 16 屏图表组件（Waffle/Ticker/Hex/Timeline/PartnerMap）参数
  也需纳入数据层，工程量约 1–2 周。
- **结论：建议单独立项，不在常规优化中执行。**

## 4.4 固定画布架构评估

### 现状
- 当前为 PPT 式实现：每屏 `.slide-inner` 按 1920×1080 设计画布，
  由 `common.js` 的 `scaleStage()` 用 `transform: scale()` 整体等比缩放铺满视口。
- 移动端（`window.innerWidth <= 820`）改为按宽度缩放、高度自然撑开可滚动。

### 问题
- 固定画布 + 整体缩放：在非常规分辨率下文字偏小/偏大；语义上仍是"缩放的画布"
  而非真响应式，不利于无障碍（缩放后字号实际变化）与 SEO 移动端评分。
- 各屏内部用绝对定位（px）布局，难以自适应断点。

### 演进方案（需立项）
1. 将 `.slide-inner` 的 1920×1080 绝对定位布局，逐步改为 `max-width:1200px`
   居中 + flex/grid 流式布局。
2. 保留视觉设计语言（金色、深色、字体），仅改布局实现。
3. 分屏灰度迁移，每屏验证桌面/平板/手机三档。
- **结论：重大改动，需出交互/视觉方案评审 + 排期，不属于本次优化范畴。**
